# Pi 透明横线消息框

已验证 **Pi 1.4.0 / 1.5.0**。不重新编译，不修改 Pi 安装目录，不改变模型请求、工具执行或会话原文。

## 工作方式

- `~/.local/bin/pi` 在 PATH 中优先于原版可执行文件；自动沿 PATH 查找原版安装，不把用户名或 Node 版本写死。
- 交互模式加载本地 JavaScript 显示补丁，再运行安装包已有的 `dist/cli.js`（未压缩入口）。
- 打印、JSON、RPC、重定向、版本查询和包管理命令直接使用原版打包入口。
- 适配明确验证过的 1.4.0 / 1.5.0 内部组件；不自动放行未知补丁版、次版本或主版本。Pi 版本不匹配或接口检查失败时，向 stderr 提示并自动回退原版，不阻止更新。
- **不是官方稳定扩展 API。** 升级后需要核对组件接口、重新测试，不能只改版本号。

## 升级后角框消失

这是版本保护触发后回退原版界面，不代表启动器或主题被删除。先运行 `pi --version` 核对版本；适配新版本后须退出并重新启动 Pi，`/reload` 不会重新加载启动补丁。

1.5.0 已核对消息 ID/时间戳、Markdown 组件复用、空标签思考隐藏、工具参数延迟渲染及新版快捷键提示接口，并增加专项回归测试。后续升级仍需核对内部接口并测试，不能仅删除版本保护或放宽版本范围。

## 显示范围

对话区的用户消息、助手回答、思考、工具调用与结果、手动 `!` 命令、扩展消息、上下文/分支摘要、技能提示及状态通知统一使用完整的四边粗线框，不铺实色底。图片协议行保持原样透传，不添加侧边，避免破坏图片显示。顶部标签嵌入横线（如 `┏━ mo ━━━━━┓`），用户发送的消息显示为 `mo`。

输入框、页脚、设置菜单等不强行套消息角框。选择和搜索使用前景色、加粗、下划线，不靠大块背景色。正常文字选择/光标仍保留原有交互反馈。

| 内容 | 角框使用的主题语义色 | myTheme 颜色 |
| --- | --- | --- |
| 用户、一般工具 | accent | 亮青 `#8be9e1` |
| 助手回答 | borderAccent | 金色 `#e8c568` |
| Shell | bashMode | 明蓝 `#9aaeff` |
| 读取、检索 | syntaxType | 浅蓝 `#b7e6ff` |
| 思考、摘要、扩展消息、技能 | syntaxKeyword / customMessageLabel | 柔紫 `#cbb3e8` |
| 编辑、写入 | success | 浅绿 `#b8efcf` |
| 警告、取消 | warning | 暖黄 `#ffe1a8` |
| 错误 | error | 浅红 `#ffb7c5` |

这些亮色是为当前深色/透明终端添加的 UI 颜色，并非原始传统色卡采样。正文保留原有语法高亮。思考是否折叠及模型思考强度仍由 Pi 本来的设置决定，补丁不修改它们。

`myTheme.json` 的消息/工具/选择/搜索背景使用空字符串（终端默认色），Foot 的透明度和模糊设置保持不变。角框还会移除输出中的背景 SGR，但保留前景色、链接和图片协议行。参考 Foot 基底 `#1e1e2e` 的角框色对比度约为 7.71–12.96:1；半透明背景的实际对比度随桌面内容变化，不作统一 WCAG 保证。

## 安装与使用

```bash
cd ~/dotfiles
mkdir -p ~/.local/lib
stow --simulate --target="$HOME" pi-ui
stow --target="$HOME" pi-ui
pi --version
```

`~/.local/bin` 必须排在原版 Pi 的 bin 目录之前。首次启用后需要**退出并重新启动 Pi**；当前已经运行的进程不能靠 `/reload` 切换启动入口。可用 `pi -c` 继续当前项目最近的会话。

原版不在 PATH 时，可临时设置 `PI_UI_AGENT_ROOT` 为 `@earendil-works/pi-coding-agent` 的包目录；不会自动下载或安装依赖。

## 停用与回滚

```bash
PI_UI_DISABLE=1 pi                       # 绕过补丁，主题仍是当前选中的主题
PI_UI_DISABLE=1 pi --use-theme dark      # 同时临时使用原版内置深色主题
cd ~/dotfiles
stow --delete --target="$HOME" pi-ui    # 移除启动器和库的链接，重新使用原版 pi
```

原主题备份位于 `~/.local/state/pi-ui-backups/`，不进入 Git。若要恢复主题，应先比较当前内容和对应备份，避免覆盖之后的新改动。
