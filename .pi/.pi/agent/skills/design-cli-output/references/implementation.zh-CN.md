## 语义配色

面向人的命令、错误和进度共享一套配色。这些是起始参考值，不是强制终端主题。

| 语义角色 | 色相 | 深色背景用淡色 | 浅色背景用深色 |
| --- | --- | --- | --- |
| `success` | 柔和绿色 | `#A7D8A8` | `#27633B` |
| `error` | 柔和红色 | `#F2A6A6` | `#A12E36` |
| `warning` | 柔和黄色 | `#E8D58B` | `#796000` |
| `info` | 柔和蓝色 | `#9FC5F0` | `#285F9A` |
| `accent` | 柔和青色 | `#9ED9D7` | `#246C6A` |
| `highlight` | 柔和紫色 | `#C6B4E7` | `#6B469B` |
| `muted` | 柔和灰色 | `#ABB3BF` | `#526071` |
| `border` | 中性灰色 | `#8D99A8` | `#657284` |

边框内的名称用 `accent`，主链接和可选的详情标题用 `info`，边框用 `border`，元数据标签用 `muted`。具体值和响应正文使用终端默认前景色。只有匹配语义时，才给状态文字及其 `○` 标记上色。`highlight` 留给选中值。即使使用颜色，也要写明状态。

已知是浅色背景时使用较深版本；不要为使淡色可读而强制改成黑底或深色背景。背景未知时，重要文本保留默认前景色，省去可能难以辨认的点缀色。相应配色在 `#18181B` 和 `#FFFFFF` 这两个参考背景上的 sRGB 计算对比度均达 4.5:1；仍应核对受支持主题的实际前景／背景组合。

## 直接 ANSI 输出

- `ESC` 是 U+001B，不是三个可打印字母。前景色用 `ESC[38;2;R;G;Bm`，RGB 通道是 0–255 的整数。仅在确有必要时用 `ESC[48;2;R;G;Bm` 设置背景色；面板通常继承终端背景。
- 每个样式片段在无样式填充或换行前以 `ESC[0m` 复位。不要测量或折行带样式的字符串；布局使用清理后的文本。关闭颜色时，既不输出样式起始序列，也不输出复位。
- 共享能力检测、文本清理、测量、折行和样式小工具。可使用 Unicode 宽度和字素分割依赖，但不用样式封装库替代直接 ANSI。

## 运行时适配

| 运行时 | 适配要点 |
| --- | --- |
| Bun TypeScript | 使用 `Bun.stringWidth` 和 `Intl.Segmenter` 等字素分割工具；`.length` 不是显示列数。 |
| Go | Unicode 显示宽度实现与字素分割结合使用；不以字节长度或 rune 数量代替显示宽度。 |
| Rust | 使用显示宽度和字素分割支持，折行与填充共享宽度策略。 |
| C | 安全处理非法 UTF-8 和缓冲区边界。`wcwidth`／`wcswidth` 受 locale 影响，不能独立处理所有字素簇。 |
| uv 管理的 Python | uv 管理环境，不负责渲染。用 Unicode 显示宽度和字素工具，不用 `len()`。 |
| Java | UTF-16 长度和码点数都不是显示宽度；使用宽度与字素工具。 |

保留项目选定的技术栈。在 Windows 上分别检查虚拟终端和 Unicode 支持，宿主不支持时选择相应的回退方式。在实际目标终端检查中英文和 emoji 混排，库的宽度估计可能与终端不同。

## 验证清单

仅在项目没有定义不同约定时应用主文档的默认规则。用下表验证各项可独立选择的表现形式，不为测试新增覆盖机制。

| 场景 | 默认规则下的预期 |
| --- | --- |
| 交互式概览，已知支持 Unicode 和 True Color，自动配色 | Unicode 面板，直接输出 24 位前景色和复位序列。 |
| 同一概览，`NO_COLOR` 非空，自动配色 | 面板几何不变，无任何样式转义序列。 |
| 自动配色，无法确认支持 True Color | 无样式转义序列；不影响边框和符号选择。 |
| 人类可读输出写入管道或文件，或 `TERM=dumb` | 无框、无装饰标记的普通文本，默认不加样式。 |
| 项目已有设置显式启用颜色，同时存在 `NO_COLOR` 或人类可读输出被重定向 | 除非已知终端宿主不能处理转义序列，否则使用颜色；该设置本身不开启面板。 |
| 终端宿主已知不能处理所需 ANSI 序列 | 按默认规则，即使显式要求也不加样式。 |
| stdout 为机器数据，stderr 接终端，即使强制配色 | 数据无装饰；单独判断 stderr 上的人类可读诊断。 |
| Unicode 符号不可用，或选用的符号不占单列 | 受影响的边框或标记使用 ASCII，不改动传入的 Unicode 文本。 |

- [ ] 用符号占一列的宽度策略验证 72 列和 40 列图例的每个框行。检查非法预算、已知不足 6 列的终端，以及 6、20、55、56、57、72、80、88 列；边框不超过已知宽度。
- [ ] 两组元数据都有字段时，验证 55 列堆叠，56 列分为两个 24 列宽的单元格，间隔四列；57 列多出的一列分给右侧。只有一组时默认单列。检查单元格分别折行、缺失侧留白和堆叠时的字段顺序。
- [ ] 测试空标题、恰好占 `面板宽度 − 5` 的标题、无法嵌入的标题、空行和显式分隔线。渲染器不追加末尾换行，调用方负责留空行分隔框外分组与面板。
- [ ] 测试混合宽度、组合字符、作为输入的 emoji 字素簇、长 URL 和路径、制表符及 CRLF。字素簇不拆分、不丢失，标签与续行对齐。测试将东亚宽度不确定字符按两列计算的策略。
- [ ] 检查传入的完整和不完整终端控制序列，包括 ANSI 和 OSC。单行值中的换行不能增加伪造状态行，多行详情保留由渲染器控制的缩进。
- [ ] 分别验证带样式和无样式的路径，包括预期的 24 位序列与复位、可辨认的状态文字和对比度。确认不改变输出契约、退出码和敏感数据处理。
- [ ] 同步维护英文指令与中文阅读版。在目标终端验证实际实现，不能把本文档当成已执行的测试。
