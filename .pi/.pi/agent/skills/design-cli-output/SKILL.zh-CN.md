# CLI 输出设计

适用于设计或修改面向人的 CLI 输出，包括终端报告、错误、进度和概览面板，以及直接 ANSI True Color、显示宽度、折行和纯文本回退。让输出平静易读：用带名称的圆角面板呈现成组的核心信息，简短状态和详情留在框外。实际实现或验证时，阅读[实现参考](references/implementation.zh-CN.md)中的配色、ANSI 序列、运行时适配和测试矩阵。

## 1. 保留输出契约

- 确认各条输出路径的目标流和受众。保留项目的 stdout/stderr 分工、退出码、现有输出模式和可解析格式。即使用户显式开启人类可读输出的样式，也不为机器可读输出添加面板、标记或样式转义序列。
- 使用项目已有的覆盖机制，不为了这套风格新增标志或模式。不为填满面板而虚构元数据、检查结果或 API 响应。
- 说明发生了什么、影响什么，必要时给出下一步操作。报告和日志都不展示敏感值。不把部分完成或失败写成成功。

## 2. 按人类可读目标流选择表现形式

检测实际目标流；stderr 连着终端，不代表重定向后的 stdout 也在终端上。将边框、颜色和 Unicode 分别判断，优先遵守项目已明确的人类可读输出约定。项目没有定义时，使用以下默认规则：

| 选择 | 默认行为 |
| --- | --- |
| 边框 | 有用的交互式概览或成组结果使用面板。独立错误、进度和逐项日志使用无框文字；文件、管道和 `TERM=dumb` 使用不带装饰标记的普通文本行。 |
| 颜色 | 已知终端宿主不支持所需转义序列时不加样式。除此之外，已有的显式用户配色设置优先于自动检测。自动模式下，`NO_COLOR` 非空、`TERM=dumb`、目标不是终端或未确认支持 True Color 时，不输出任何样式（包括复位和粗体）。只有 TTY 不构成支持依据；`COLORTERM=truecolor` 和 `COLORTERM=24bit` 可作参考。 |
| Unicode 装饰 | 只有在符号可正常渲染，且所选每个符号在目标宽度策略下都占一列时，才使用线框字符和框外标记。某组符号不受支持，或无法确认其在该宽度策略下占一列时，回退至 ASCII。这不要求改写内容本身的 Unicode 字符。 |

只有 `NO_COLOR` 时，不必移除面板或 Unicode 字符。对于重定向的人类可读输出，显式强制配色可以给普通文本行着色，但不会开启面板。自定义颜色直接用 24 位 ANSI，不使用样式封装库，也不替换为 16／256 色。共享柔和的语义配色，继承终端背景和正文默认前景色，用文字明确表达每种状态。避免荧光色、渐变和大面积背景填色。

## 3. 布局前准备文本

- 将传入的标题、URL、路径和响应视为文本。移除嵌入的终端转义／控制序列（包括不完整的序列）及不安全控制字符。只为下述字段规范化保留换行和制表符。关闭颜色时也要清理。
- 将 CRLF 和单独的 CR 统一成 LF。标题、链接、元数据、状态值等单行字段中的换行替换为空格。只在指定的多行详情字段中保留换行，续行缩进由渲染器添加。测量前将制表符替换成四个空格。
- 按终端显示列测量，不按字节、UTF-16 单元或码点计数。使用字素簇分割，测量、折行、填充采用同一套宽度策略。优先从词边界折行；长连续文本从字素边界折行，不截断。如果连一个完整字素簇都放不下，改用无框文字，不强行拆开。
- 渲染器保持纯函数：接收准备好的内容、宽度和表现设置，返回文本，不负责打印。布局完毕后才附加可信 ANSI 样式。

## 4. 布局概览与框外文字

- 主要结果只用一个面板，仅为真正独立的结果增加面板。名称嵌在顶边靠左的位置。把原样展示的主 URL 或位置放在正文最前，占用全部内部宽度；没有则省略。放得下就占一行，否则折行，不截断。下方放概览信息或最终结果，用留白分组，不自动加分隔线。常规状态、数据库状态和 API 详情放在框外；成组的关键失败信息可在框内给出原因和修复操作。
- 列宽预算缺失、非有限数或非正数时默认 80；否则向下取整，限制在 6–88 列。已知目标流对应的终端宽度时，以它为上限；不足 6 列则使用无框文字。
- 两组有序元数据均非空，且预算至少 56 列时，选用双列，面板首选宽度为 `min(预算, 72)`；其余情况选用单列，首选 `min(预算, 40)`。长标题或主链接可在预算内加宽面板。单列保留所有字段，先列出第一组，再列出第二组。
- 正文行依次是侧边框、一个空格、填充到 `面板宽度 − 4` 的内容、一个空格和侧边框。双列留四列间距，其余内部宽度平分（多出的一列给右侧），成对字段分别折行。较短一侧的续行补空白，没有配对字段的一侧保持空白。所有边框行占用相同显示宽度。
- 使用 `╭`、`╮`、`╰`、`╯`、`─`、`│` 绘制边框。非空标题能放进 `面板宽度 − 5` 时，以 `╭─ <标题> ` 开头，补足 `─` 后用 `╮` 收尾。否则使用无标题顶边，在正文中折行展示标题，之后留一空行。空标题不加标题行。空内容行仍填充至边框；仅在明确要求时使用 `├`、`┤` 生成分隔线。渲染结果用换行符连接，不带末尾换行；有框外状态区时，与面板间隔一空行。
- `○` 用于状态，`◇` 用于详情标题，均须带文字。`○` 不代表成功。详情和续行缩进，对齐标记与空格之后的文字。Unicode 装饰不可用时，使用 `+`、`-`、`|` 绘制 ASCII 边框，两类标记均用 `-`。如果前缀和标签首个字素簇无法同时放下，省略标记与缩进。不加其他装饰符号、图标、emoji 或动画；本规则不限制输入文本自带的符号。

## 5. 验证结果

分别检查有样式的交互流、无样式的交互流，以及重定向或机器可读输出。检查 55／56 列切换点、混合宽度文本，以及传入控制字符和换行的安全处理。用目标技术栈完成参考文档的[验证清单](references/implementation.zh-CN.md#验证清单)；仅复现图例不能证明终端兼容性。
