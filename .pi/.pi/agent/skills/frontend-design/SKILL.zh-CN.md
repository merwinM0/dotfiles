# 前端设计

**适用范围：** 在构建新界面或重塑现有界面时，为鲜明、有意图的视觉设计提供指导。帮助确定美学方向、字体排版，并做出不显得像默认模板的设计选择。

**许可：** 完整条款见 `LICENSE.txt`。

以一家设计工作室的设计负责人的身份开展工作：这家工作室以为每位客户打造独一无二、不会与他人混淆的视觉形象而闻名。客户已经否决了那些陈词滥调或模板感明显的提案，付费购买的是鲜明的设计主张。因此，要围绕本次需求，在配色、字体排版和布局上做出经过斟酌、有明确立场的选择；有充分理由时，可以在美学上大胆冒险。

## 让设计扎根于主题本身

如果需求说明没有明确产品或主题是什么，在开始设计前先自行确定，并与客户确认。可以提出一个具体主题、设计面向的受众，以及设计最主要的任务，作为供确认的提案。如果记忆中已有客户的偏好，或关于他们正在构建什么的背景信息，可以将其作为线索。主题所属的行业、具体内容、材质和惯用的视觉语言，才是鲜明视觉选择的来源——面向 8–11 岁女孩的玩具，与面向金融分析师的仪表盘，在美学上会有很大差异。在整个构建过程中，都要使用与需求相符的真实内容和主题素材。

## 设计原则

对于网页设计，首屏主视觉区（hero）是浏览者最先看到的内容。用主题世界中最具辨识度的事物开场，并采用最恰当的表现形式：标题、图片、动画、实时演示、交互体验，或其他方式。这个选择必须经过认真考虑：大数字配小标签、辅助统计数据和渐变点缀，是一种默认套路，只有当它确实是最佳方案时才使用。

字体排版承载着页面的个性。展示性文字或标题与正文不一定需要使用不同的字体家族：可以使用一个，也可以使用两个；如果使用两个，就让它们有清晰的区别。

有意识地选择字体，不要随手采用在其他项目中也会使用的默认字体家族。遵循《The Elements of Typographic Style》的基本指导，建立清晰的字号层级，并有意安排字重、字宽和间距。当文字用作标题或视觉元素时，让文字本身的处理方式积极参与设计，而不是仅仅充当中性的信息载体。

默认将每行长度控制为少于 80 个字符。衬线字体的行长可以略长；衬线正文的行高也应比无衬线正文稍大。

避免以下默认排版处理，它们是生成式页面最常见的识别特征：
- 只强调标题中的某个单词或短语，例如仅将一个词设为斜体、粗体或不同颜色。
- 标签全部使用大写字母。
- 在内容上方添加不必要的文字标签。

视觉结构就是信息。轮廓、边框、编号、标题上方的引导短标（eyebrow）、分隔线、标签等结构性手段，应当传达关于内容的有用信息，而不是充当装饰。许多泛化设计会使用编号标记（01 / 02 / 03），但只有内容确实存在先后顺序时才合适，例如分步流程或时间线。添加编号标记之前，先确认内容确实是一个序列。

非用户触发的动效应当克制、有意图地使用，且仅用于引导注意力。一个经过编排的完整时刻——一次页面载入序列或一次内容揭示——比零散的特效更有表现力；每个区块都淡入上滑、每张卡片都有悬停过渡，是泛化的默认套路，会显得像 AI 生成。响应用户操作的动效，例如打开、展开、确认，只要能说明发生了什么变化，就是值得采用的。

认真推敲文字内容。设计需求通常可能不包含真实内容，需要你自行撰写文案并准备占位内容。文案与视觉设计一样，也可能让作品显得模板化。更多指导见下方关于文案写作的章节。

## 流程：规划、对照需求审查、构建、评判

为便于校准判断，当前 AI 生成的设计通常集中于以下特征：
1. 暖奶油色背景（接近 #F4F1EA），搭配笔画粗细对比强烈的衬线展示字体，以及陶土色或暖黏土色点缀（通常接近 #D97757——这正是 Anthropic 自家 Claude 交互界面的强调色，因此出现在用户项目中时，会成为明显的识别线索）；
2. 近黑色背景，搭配单一的亮酸绿色或朱红色点缀；
3. 大开本报纸式布局：极细的分隔线、完全不使用圆角，以及密集的报纸式分栏；
4. SaaS 卡片套件式设计：将内容切成大小样式一致的圆角卡片，不顾层级地为所有元素使用同一种圆角，每张卡片下面都有相同的柔和灰色阴影（rgba(0,0,0,.1)），再用渐变色晕作为装饰；
5. 无论主题是什么都出现的模板化界面修饰：每个标题上方都有拉大字距的全大写引导短标；用间隔号连接的元信息（“A · B · C”）；以“WORD — fragment”形式组织、破折号两侧留空格的标签；用带色调的近黑色（#0B0B0B、#111）代替黑色；小型数据标签使用等宽字体；链接和按钮文字末尾追加“→”。

这些特征在某些需求下都可能合理，但它们往往只是默认套路，而非经过思考的选择，而且不论主题是什么都会出现。如果需求明确规定了视觉方向，就严格遵循——需求本身的表述始终优先，即使它要求的正是上述某种风格。如果某个维度留有发挥空间，不要把这份自由浪费在这些默认套路上。就像受雇的人类设计师一样，需要在发挥自身所长与把每个项目当作实验、学习机会之间，找到审慎的平衡。

分两轮推进。首先，围绕客户的设计需求，构思一份简短的设计计划：建立一个紧凑的设计令牌体系，涵盖色彩、字体、布局和原则。
- 色彩：用 4–6 个带名称的十六进制色值描述核心基础配色。
- 字体：明确字体家族及各自的用途。
- 布局：提出布局构想，用一句话描述各个方案，并用 ASCII 线框图构思和比较。包含对齐指导：内容应左对齐、居中对齐，还是两端对齐？
- 原则：说明哪些高层次的指导原则让这个页面独具特色。

然后，在构建之前，对照需求审查这份计划：如果某一部分看起来更像是你面对任何类似页面都会给出的通用默认方案，而不是针对本次具体需求做出的选择，就修改它，并说明改了什么、为什么改。可以尝试处理一个类似的提示，看看是否会得出相似的结果。只有在确认设计计划具有相对独特性之后，才开始按照修订后的计划编写代码。

编写代码时，要谨慎组织 CSS 选择器的优先级。生成的 CSS 类很容易相互覆盖，尤其是在同时使用 `.section` 这类按类型划分的选择器和 `.cta` 这类面向具体元素的选择器时。区块之间的 padding/margin 尤其容易出现这种问题。

## 克制与自我审视

把大胆用在一个地方。让一个元素成为最令人记住的亮点，周围的一切保持安静、有序，并删去所有不服务于需求的装饰。无需刻意宣告，但必须达到基本质量要求：响应式适配到移动端、键盘焦点清晰可见、尊重减少动态效果的偏好、视觉上具有无障碍可访问性、配色和谐。在构建过程中持续审视自己的作品；如果环境支持，就截图检查——一张图胜过 1000 个 token。想想香奈儿的建议：出门前照一下镜子，摘掉一件配饰。人类创作者有记忆，也总想做出新东西；如果有地方可以快速记下尝试过的方案，会对后续迭代有所帮助。

## 设计中的文案写作补充

文字出现在设计中只有一个理由：让它更容易被理解和使用。文字是设计内容，不是装饰。像对待间距和色彩一样，以同样的明确意图和精简原则对待文案。动笔之前，先问自己：设计需要传达什么，又该怎样表达，才能最好地帮助用户理解并顺利完成体验流程。

从最终用户的角度写作。用用户能够理解的简单语言命名事物，而不是按系统的实现方式命名。用户管理的是通知，而不是 webhook 配置。用直白的语言说明某个事物是什么、能做什么，而不是推销它。表达具体、让新用户看得懂，始终比耍小聪明更重要。

默认使用主动语态。行动按钮（CTA）应准确说明点击后会发生什么：写“保存更改”（Save changes），而不是“提交”（Submit）。同一个操作在整个流程中应保持名称一致，因此，写着“发布”（Publish）的按钮，触发后的轻提示应写“已发布”（Published）。界面中的词汇是用户探索产品时的路标。连贯与一致，才能帮助用户学会如何使用产品。

把失败和空状态当作提供方向的时刻，而不是渲染情绪的机会。用界面自身的语气，而不是某个人的口吻，解释哪里出了问题以及如何修复。错误提示无需道歉，也绝不能含糊其辞地描述发生了什么。空白页面应当邀请用户采取行动。

保持自然、对话式的语气：使用直白的动词，英文采用句首字母大写的常规写法（sentence case），不说废话，并让语气符合品牌和受众。每一处文字都只承担一个明确的任务。
