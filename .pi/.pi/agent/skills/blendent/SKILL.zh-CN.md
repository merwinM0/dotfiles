# Blendent：浅色优先的青色配色设计

**技能名：** `blendent`

**适用范围：** 参考所提供的中国传统青色（青、蓝绿及蓝青）色卡，设计、实现和审查浅色优先的 UI 配色。用于选色、定义语义化设计令牌、设置组件与交互状态、改善对比度和审查视觉一致性。优先明亮、通透的界面及克制的青色强调，同时遵守明确的品牌、主题和无障碍要求。

## 目标与边界

构建明亮、平静、易读的青色系界面。**优先浅色主题和高明度表面，而不是到处使用高饱和色。** 深色用于可读文字及小面积、有目的的交互强调，不默认铺设大块深色面板。

本技能负责配色决策，不规定框架、布局、排版或组件架构。应与项目的 UI 工程规范配合使用。用户明确要求、既有品牌规范和无障碍要求优先于默认色板。未经授权，不要给成熟产品整体换色。

## 色值来源

选择或修改色值前，阅读本技能目录中的 `青.md`。其中包含从浅到深排列的 50 个命名 HEX/RGB 色样。

- 色值来自有纹理和压缩的图片近似采样，不是历史颜色的统一标准定义。
- 引用原始色样时保留名称和 HEX 值，不杜撰历史寓意或声称具备权威色彩准确性。
- 代码使用稳定的 ASCII 令牌名；文档可以标注中文色名。
- 必要时允许添加中性色、状态色及派生色，但应明确其为新增颜色，而非原始色卡颜色。
- 正常执行不需要加载本中文翻译，它仅供人工阅读。

## 工作流程

1. 检查现有令牌、主题行为、品牌约束、组件状态及实际背景，保护用户无关改动。
2. 判断任务是新建色板、局部扩展还是修复对比度，尽量保留既有语义。
3. 选择浅色基底、一个主要强调色系、可读文字色及功能状态色，不要把 50 个色样全部用上。
4. 先定义语义令牌，再编写组件样式，记录新增或派生颜色。
5. 按需统一应用默认、悬停、按下、选中、聚焦、错误和禁用状态。
6. 计算实际前景/背景组合的对比度，再使用可用浏览器工具检查渲染界面。如实说明未验证项目。

## 浅色优先的构成

- 默认页面背景：月白 `#EBF5F7`，或项目认可的浅中性色。
- 默认内容表面：白色或近白色；次要区域可用青白 `#DCEFED` 轻微区分。
- 浅青 `#BEE7E3` 用于选中背景和克制强调，不作正文文字色。
- 玄青绿 `#245E64` 或青黛 `#29525E` 用于主要操作、链接和强强调。
- 青黑 `#122E3A` 用于主要文字；次要文字也要足够深、容易阅读。
- 可见面积可先按约 70–85% 浅色表面、10–20% 次要浅染色表面、5–10% 强强调分配。这是经验起点，不是硬性指标，更不能以此削弱层级。
- 优先纯色。可选渐变必须细微、色相相近且不妨碍阅读。默认不引入荧光青、彩虹渐变或深色首屏。
- 不强迫所有元素变绿。通过留白、中性表面及克制强调建立层级。

## 默认语义令牌

应适配项目既有令牌体系，不做无必要替换。白色是新增中性色，不是传统色卡采样色。

```css
:root {
  color-scheme: light;
  --color-bg: #EBF5F7;               /* 月白 */
  --color-surface: #FFFFFF;          /* 新增中性色 */
  --color-surface-subtle: #DCEFED;    /* 青白 */
  --color-surface-selected: #BEE7E3;  /* 浅青 */

  --color-text: #122E3A;             /* 青黑 */
  --color-text-secondary: #29525E;   /* 青黛 */
  --color-text-muted: #326C77;       /* 幽青 */

  --color-accent: #245E64;           /* 玄青绿 */
  --color-accent-hover: #29525E;
  --color-accent-active: #183E50;    /* 藏青 */
  --color-on-accent: #FFFFFF;
  --color-link: #245E64;

  --color-border-subtle: #B4E2DC;    /* 雾青；装饰性边线 */
  --color-border-control: #3C878C;   /* 深青 */
  --color-focus-ring: #245E64;
}

/* 按需将这些语义角色映射到现有组件类。 */
.primary-action {
  color: var(--color-on-accent);
  background: var(--color-accent);
}
.primary-action:hover { background: var(--color-accent-hover); }
.primary-action:active { background: var(--color-accent-active); }
.primary-action:focus-visible {
  outline: 3px solid var(--color-focus-ring);
  outline-offset: 3px;
}
```

焦点环示例假定周围是浅色表面。在深色表面使用时应重新检查，或采用双色焦点指示。产品有意支持多个主题时，不要全局强加 `color-scheme: light`。

## 对比度与无障碍

使用 WCAG 相对亮度与对比度计算，不依赖直觉或颜色名称：

- 普通文字至少 **4.5:1**；大号文字至少 **3:1**，大号指常规 18 pt 或粗体 14 pt，约为 24 px 或 18.7 px。
- 必需的控件边界、有意义图标和视觉状态指示，在 WCAG 非文本对比度适用时，与相邻颜色至少 **3:1**。
- 焦点必须可见且不被遮挡，不仅靠细微背景色变化表示。
- 不只靠颜色传达意义；按需添加文字、图标、下划线、图案或形状。
- 浅色细分隔线可以仅用于装饰，但不能是识别必要控件边界的唯一方式。
- 禁用控件豁免这些 WCAG 对比度要求，但仍应能够辨认。可操作内容不能套用禁用样式。

以下为不透明 sRGB 颜色的参考计算，四舍五入保留两位小数：

| 前景 | 背景 | 对比度 | 用途 |
| --- | --- | --- | --- |
| `#122E3A` | `#EBF5F7` | 12.82:1 | 主要文字 |
| `#29525E` | `#EBF5F7` | 7.69:1 | 次要文字 |
| `#326C77` | `#EBF5F7` | 5.34:1 | 弱化但仍可读的文字 |
| `#FFFFFF` | `#245E64` | 7.34:1 | 主要按钮文字 |
| `#183E50` | `#BEE7E3` | 8.53:1 | 选中背景上的文字 |
| `#3C878C` | `#FFFFFF` | 4.17:1 | 控件边界，不用于普通文字 |
| `#3C878C` | `#EBF5F7` | 3.76:1 | 控件边界，不用于普通文字 |

这些检查不代表所有使用方式都合格。透明度、叠层、渐变、图像、其他背景和各交互状态均需重新计算。浅青色通常适合表面，不要假定中等深浅的青色背景配白字就可读。

## 功能颜色与状态

- 如果会模糊意义，不要让成功、警告、危险和信息全部使用相同青色。
- 保留已有且可访问的状态令牌。若没有，则引入少量可区分的状态色，配合浅色背景、深色标签、图标及清晰措辞。逐组验证对比度，标明新增颜色。
- 选中项增加非颜色标记，例如勾选、边框或辅助技术可识别的选中状态；选中与悬停保持可区分。
- 错误应有可操作文字并关联字段，不只是红色边框。成功也不能只依赖绿色。
- 多系列图表需使用可区分色相或冗余编码；不要把大量近似青色硬塞进分类图表。
- 不要通过降低整个组件透明度来弱化文字，因为这会改变全部实际对比度组合。

## 主题行为

除非用户或产品明确要求，否则新界面默认浅色。不要只因其他产品常这样做，就默默跟随系统深色偏好、添加深色主题或持久化新的主题偏好。保留现有主题切换和用户选择。用户要求深色模式时，单独定义并测试语义映射，不能机械反转浅色色板。

## 验证与交付

- 检查所有相关文字/背景组合、控件边界、链接、焦点环和交互状态。
- 检查真实页面渲染，包括实际存在的表单、对话框、表格、选中行、通知和图表。
- 检查键盘焦点及不依赖颜色的语义。工具可用时以灰度或色觉模拟审查，但它们不能替代对比度计算。
- 按变更运行现有项目检查。仅修改配色文档时，不必凭空创建应用构建。
- 报告所选色板与令牌变化、实测对比度、实际执行检查及剩余视觉限制。未发生的浏览器或色觉测试不能声称完成。
